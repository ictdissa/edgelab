# Publication Hardening: 2026-11-16

Research-only release. No new market-data collection, orders or profitability
evidence was generated by this hardening pass.

## Correctness Fixes

- Unsupported margin, double-chance, negated, compound and period-specific
  fixture questions abstain instead of inheriting a match-winner probability.
  The check runs at matching, valuation, signal and independent risk boundaries.
  A supplied category, target outcome or serialized action cannot bypass it.
- Binary target inference requires an unambiguous question subject. An incidental
  first team name no longer overrides the subject nearest the winning verb.
  An outright title cannot become a fixture merely because its description
  mentions an upcoming game.
- Fixture participants are derived from category/contract-compatible odds rows.
  Adding totals or another contract cannot turn Over/Under labels into teams.
- Provider interfaces no longer eagerly re-export dependent implementations.
  All EdgeLab modules are tested in network-blocked fresh Python processes.
- Unknown provider market names stay unknown rather than silently becoming
  moneylines. Invalid kickoff data cannot promote an existing rejection to review.
- Legacy binary complement synthesis and outright pricing/rewriting are disabled.
  The retained predecessor is explicitly deprecated, not a supported second engine.

## Evidence And Limits

The public README now focuses on the method, commands, results and limitations.
Module descriptions distinguish implemented calculations from disabled adapters.
Historical summary reports use diagnostic language rather than application claims;
design/software checks not performed by the report are marked NOT_EVALUATED.
Personal application wording remains local and is excluded from source exports.

The new regression cases reproduce failures found after the earlier 350-case
suite had passed. Their repair improves software correctness, not predictive
accuracy or trading profitability. See the latest [validation record](../reports/public/validation.md).

The only disclosed live feasibility observation remains 2026-10-13. No new
real-data edge, CLV, fill, settlement return or held-out result is claimed.
Costs, source quality, actual fills and uncertainty still require calibration.
The classifier remains a conservative rule system, not a universal payoff parser.

Only upload the newly verified allowlisted package. Private data and previous
archives remain local; disclosed credentials still require account-side rotation.
Hosted CI and Git history require checks after repository creation.
